# Hypothesis-Based Code Verification Rule

- **핵심 지침**: 단시안적/표면적 증상 수정을 엄격히 금지한다.
- **수행 절차**:
  1. 문제가 발생하거나 요구사항이 변경될 때, 전체 코드베이스와 객체 생명주기(Lifecycle) 및 아키텍처 맥락을 바탕으로 **최소 3가지 이상의 다양한 가설(Hypotheses)**을 수립한다.
  2. 세운 가설들을 실제 코드 구조, 타입, 인자 전달 및 실행 흐름 단위로 정밀하게 검증하여 진짜 근본 원인을 선별한다.
  3. 검증된 근본 원인에 대해서만 안전하고 완벽한 수정을 진행하고 보고한다.
